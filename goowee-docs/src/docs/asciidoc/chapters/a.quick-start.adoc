== Goals
*Build enterprise applications with AI or through traditional coding: describe your application in a prompt for the `goowee-developer` agent, or implement it yourself with the Goowee API.*

Goowee applications are designed to:

. Run as Progressive Web Applications on desktops, tablets and phones, with a native-like installable experience.
. Deploy on your own infrastructure, in the cloud, or as a service.
. Authenticate users with local credentials, hardware tokens, LDAP and Active Directory, IBM i, or OpenID Connect.
. Serve multiple tenants from one codebase, with a separate database and isolated data for each tenant.
. Give users a familiar, consistent interface across applications.
. Support keyboard navigation for users familiar with legacy systems such as AS/400.
. Localize applications with built-in internationalization.

NOTE: Goowee separates business logic from the _User Interface (GUI)_, which can reduce maintenance costs. Developers can focus on application code instead of maintaining a separate front end with HTML, CSS, and JavaScript.

== Non-Goals
*Goowee is designed for enterprise applications that benefit from a consistent, component-based interface. It may not be the right fit for:*

. Simple, content-focused websites made up primarily of text, images, and basic interactions.
. Highly visual or animation-heavy web applications.
. Projects where the client needs strict control over the look and feel of the user interface.

For these cases, the https://grails.org/[Apache Grails,window=_blank] framework may be a better fit because it offers more flexibility for building a custom interface.

== Basics
In Goowee, everything is a component. Every visual element derives from the `Component` base class, so you can assemble an interface much like a set of LEGO bricks.

The `org.goowee:goowee-core` Grails plugin automatically creates and manages some components for each application. Let's take a closer look.

=== Project Structure
Goowee applications are Grails applications. Their project structure follows the _convention over configuration_ principle, with each folder containing a specific type of source file.

----
/myapp                      <1>

  /grails-app               <2>
    /controllers            <3>
    /services               <4>
    /domain                 <5>
    /i18n                   <6>
    /init                   <7>
    /conf                   <8>

  /src
    /main
      /groovy              <9>
----
<1> Project root
<2> Web application root
<3> User interface. Controller classes in this directory must end with `Controller` (for example, `PersonController`).
<4> Business logic. Service classes in this directory must end with `Service` (for example, `PersonService`).
<5> Domain model. Domain classes in this directory must begin with `T` (for example, `TPerson`).
<6> Translations
<7> Initialization
<8> Configuration files
<9> Other application source files

Files in these folders follow the application's package structure. For example, if the main package is `myapp`, the source tree looks like this:

----
/myapp
  /grails-app

    /controllers
      /myapp
        MyController.groovy

    /services
      /myapp
        MyService.groovy

    /domain
      /myapp
        MyDomainClass.groovy

    /init
      /myapp
        BootStrap.groovy

  /src
    /main
      /groovy
        /myapp
          MyClass.groovy
----

=== Features

A Goowee application contains a set of _Features_.

Each feature groups visual elements that help users complete a specific task. Features appear as items in the Application Menu on the left; selecting one displays its content.

Register application features in `BootStrap.groovy`.

./grails-app/init/BootStrap.groovy
[source, groovy]
----
class BootStrap {

    GooweeApplication gooweeApplication // <1>

    def init = {
        gooweeApplication.onInit { // <2>
            registerFeature( // <3>
                controller: 'person',
                icon: 'fa-user',
            )
        }
    }
}
----
<1> `GooweeApplication` configures the application.
<2> Grails runs the `init = { ... }` closure each time the application starts.
<3> Inside `gooweeApplication.onInit { ... }`, you can call any `gooweeApplication` method. Here, we call xref:z.api-reference.adoc#registerFeature[`registerFeature()`].

=== Controllers

A _Feature_ links to a _controller_, which contains one or more _actions_.

Actions that users can take in an application, such as selecting a button, are implemented as methods in a _controller_ class. Each action corresponds to a URL that the browser sends to the server. The URL follows this structure:

----
http://my.company.com/${controllerName}/${actionName}
----

For example, the following controller defines two actions that you can call at these URLs:

----
http://my.company.com/person/index <1>
http://my.company.com/person/edit/1 <2>
----

[source, groovy]
./grails-app/controllers/PersonController.groovy
----
class PersonController implements ElementsController {

    def index() { // <1>
        display ...
    }

    def edit() {  // <2>
        def id = params.id //<3>
        display ... //<4>
    }

}
----
<1> The `index` action is the default action, so you can omit its name and call `http://my.company.com/person`.
<2> The `edit` action receives `1` as the `id` parameter.
<3> The implicit `params` variable is a `Map` of submitted parameters. Here, it contains the `id` from the `edit` URL.
<4> The `display` method ends the action and tells the browser which component to display.

=== Services
Keep business logic out of controllers and put it in _services_. A service is a class whose methods can be called from a controller.

For example, the following service provides a `sayHello()` method.

[source, groovy]
./grails-app/services/PersonService.groovy
----
@Slf4j
@CurrentTenant
@CompileStatic
class PersonService {

    String sayHello() {
        log.info "Saying hello to the folks!"
        return "Hi folks!"
    }

}
----

A controller can call it like this:

[source, groovy]
./grails-app/controllers/PersonController.groovy
----
class PersonController implements ElementsController {

    PersonService personService // <1>

    def index() {
        def hello = personService.sayHello()
        display message: hello // <2>
    }

}
----
<1> The service is injected here. Its variable name is the `camelCase` version of the class name.
<2> The `display` method renders content in the browser; here, it displays a message.

=== Domain

Use https://gorm.grails.org/["GORM, the Grails Object Relational Mapper",window=_blank] to map database tables to domain classes. For example:

[source, groovy]
./grails-app/domain/TPerson.groovy
----
class TPerson implements GormEntity, MultiTenant<TPerson> { //<1>

    String firstname
    String lastname
    String address

    static constraints = {
        address nullable: true
    }
}

----
<1> Goowee domain class names start with `T`, making domain classes easy to recognize in the code.

=== Database Connections

Each application has a `DEFAULT` database connection configured in `grails-app/conf/application.yml`. Goowee uses this connection to store its own data, and the connection cannot be changed at runtime.

. Configure multiple databases for each environment (such as development, test, and production) in `application.yml`. See the https://docs.grails.org/latest/guide/single.html#environments[Grails environment guide,window=_blank].

. Create or edit database connections at runtime in the Goowee interface. Sign in as `super` and select `System Configuration -> Connection Sources`.

. You can also create database connections programmatically at runtime with `ConnectionSourceService`:

./grails-app/init/BootStrap.groovy
[source, groovy]
----
class BootStrap {

    GooweeApplication gooweeApplication // <1>
    ConnectionSourceService connectionSourceService // <2>

    def init = {
        gooweeApplication.onTenantInstall { String tenantId -> // <3>
            connectionSourceService.create( // <4>
                name: 'runtimeDatasource',
                driverClassName: 'org.h2.Driver',
                dbCreate: 'update',
                username: 'sa',
                password: '',
                url: 'jdbc:h2:mem:DYNAMIC_CONNECTION;LOCK_TIMEOUT=10000 DB_CLOSE_ON_EXIT=TRUE',
            )
        }
    }

}
----
<1> `GooweeApplication` configures the application.
<2> `ConnectionSourceService` is injected here.
<3> The `onTenantInstall { ... }` closure runs the first time the application starts for the `DEFAULT` tenant and whenever a new tenant is created.
<4> The `create()` method adds a connection. Goowee reconnects to it on subsequent starts. To change its details, sign in as `super` and select `System Configuration -> Connection Sources`.

=== Tenants

_Multi-tenant_ applications share one codebase while connecting each tenant to a separate database, usually one per company. This keeps tenant data separate.

Users can belong to only one tenant. Anyone who needs access to multiple tenants must have a separate account in each one. Sign in as a tenant admin to manage that tenant's users. Goowee creates a default admin user for each tenant, using the tenant name in lowercase (for example, the `TEST` tenant has a `test` admin user).

NOTE: A default admin user's password matches its username. Sign in as that user and change the password under `User Menu (top right) -> Profile`.

To create a tenant, sign in as `super` and select `System Configuration -> Tenants`. If your application does not need multiple tenants, use the `DEFAULT` tenant, which Goowee creates automatically.

=== User Management

Users sign in to a Goowee application with a username and password. A tenant admin manages users and groups under `Tenant Administration -> Users` and `Tenant Administration -> Groups`.

== CRUD Applications
One common user-interface pattern is CRUD (Create, Read, Update, and Delete), the four basic operations for working with persistent data.

This example registers a feature for working with movies (see xref:z.api-reference.adoc#features[Features]).

.grails-app/init/BootStrap.groovy
[source,groovy]
----
class BootStrap {

    GooweeApplication gooweeApplication // <1>

    def init = {
        gooweeApplication.onInit {
            registerFeature( // <2>
                controller: 'movie',
                icon: 'fa-film',
                favourite: true,
            )
        }
    }
}
----
<1> See xref:z.api-reference.adoc#application[Application].
<2> See xref:z.api-reference.adoc#registerFeature[`registerFeature()`].

Next, define a simple data model with https://gorm.grails.org/[GORM for Hibernate,window=_blank], then build the user interface on top of it.

.grails-app/domain/TMovie.groovy
[source,groovy]
----
class TMovie implements GormEntity, MultiTenant<TMovie> {

    LocalDateTime dateCreated
    String title
    Integer released

    static hasMany = [actors: TActor]

    static constraints = {
        title nullable: false
    }
}
----

.grails-app/domain/TActor.groovy
[source,groovy]
----
class TActor implements GormEntity, MultiTenant<TActor> {

    LocalDateTime dateCreated
    String firstname
    String lastname

    static constraints = {
        firstname nullable: false
        lastname nullable: false
    }
}
----

To build the CRUD interface, define controller actions for displaying forms and handling updates. Keep the business logic in a service so it stays separate from the user interface.

.grails-app/controllers/BookController.groovy
[source,groovy]
----
@Secured(['ROLE_CAN_EDIT_MOVIES']) // <1>
class MovieController implements ElementsController { // <2>

    def index() {
        // will display a list of movies
    }

    def create() { //<3>
        // will display a form with the movie title
    }

    def onCreate() { // <3>
        // will create the movie record on the database
    }

    def edit() {
        // will display the details of a movie
    }

    def onEdit() {
        // will update the movie record on the database
    }

    def onDelete() {
        // will delete a movie record from the database
    }
}
----
<1> Only users with the `ROLE_CAN_EDIT_MOVIES` authority can access this controller's actions.
<2> Implementing `ElementsController` exposes the Goowee API to this controller.
<3> By convention, name actions that display the interface with a verb or noun. Prefix actions that execute business logic with `on`.

Use `ContentTable` to list records and `ContentCreate` and `ContentEdit` to create and edit them (see xref:z.api-reference.adoc#contents[Contents]).

.grails-app/controllers/BookController.groovy
[source,groovy]
----
@Secured(['ROLE_CAN_EDIT_MOVIES'])
class MovieController implements ElementsController {

    MovieService movieService // <1>

    def index() {
        def c = createContent(ContentTable)
        c.table.with {
            filters.with {
                addField(
                    class: TextField,
                    id: 'find',
                    label: TextDefault.FIND,
                    cols: 12,
                )
            }
            sortable = [
                title: 'asc',
            ]
            columns = [
                'title',
                'released',
            ]

            body.eachRow { TableRow row, Map values ->
                // Do not execute slow operations here to avoid slowing down the table rendering
            }
        }

        c.table.body = movieService.list(c.table.filterParams, c.table.fetchParams)
        c.table.paginate = movieService.count(c.table.filterParams)

        display content: c
    }

    private buildForm(TMovie obj = null) {
        def c = obj
                ? createContent(ContentEdit)
                : createContent(ContentCreate)

        c.form.with {
            validate = TMovie
            addField(
                class: TextField,
                id: 'title',
            )
            addField(
                class: NumberField,
                id: 'released',
            )
        }

        if (obj) {
            c.form.values = obj
        }

        return c
    }

    def create() {
        def c = buildForm()
        display content: c, modal: true
    }

    def onCreate() {
        def obj = movieService.create(params)
        if (obj.hasErrors()) {
            display errors: obj
            return
        }

        display action: 'index'
    }

    def edit() {
        def obj = movieService.get(params.id)
        def c = buildForm(obj)
        display content: c, modal: true
    }

    def onEdit() {
        def obj = movieService.update(params)
        if (obj.hasErrors()) {
            display errors: obj
            return
        }

        display action: 'index'
    }

    def onDelete() {
        try {
            movieService.delete(params.id)
            display action: 'index'

        } catch (e) {
            display exception: e
        }
    }
}
----
<1> The service is injected here; see its implementation below.

Use https://gorm.grails.org/[GORM for Hibernate,window=_blank], Grails' default object-relational mapper, to implement the database operations.

.grails-app/services/MovieService.groovy
[source,groovy]
----
import grails.gorm.DetachedCriteria
import grails.gorm.multitenancy.CurrentTenant
import grails.gorm.transactions.Transactional
import groovy.contracts.Requires
import groovy.transform.CompileDynamic
import groovy.transform.CompileStatic

@CurrentTenant
@CompileStatic
class MovieService {

    @CompileDynamic
    private DetachedCriteria<TMovie> buildQuery(Map filterParams, Boolean readOnly = false) {
        def query = TMovie.where {}

        if (filterParams.containsKey('id')) {
            query = query.where { id == filterParams.id }
        }
        if (filterParams.containsKey('dateCreated')) {
            query = query.where { dateCreated == filterParams.dateCreated }
        }
        if (filterParams.containsKey('title')) {
            query = query.where { title == filterParams.title }
        }
        if (filterParams.containsKey('released')) {
            query = query.where { released == filterParams.released }
        }

        if (filterParams.find) {
            String search = filterParams.find.replaceAll('\\*', '%')
            query = query.where {
                title =~ "%${search}%"
            }
        }

        // Add additional filters here

        query.readOnly(readOnly)
        return query
    }

    private Map getFetchAll() {
        // Add any relationship here
        // like references to other DomainObjects or hasMany
        return fetch + [
            actors: 'join',
        ]
    }

    private Map getFetch() {
        // Add only single-sided relationships here
        // like references to other Domain Objects
        // Do not fetch hasMany relationships in paginated lists,
        // they can cause pagination issues.
        return [:]
    }

    TMovie get(Serializable id) {
        return find(id: id)
    }

    TMovie find(Map filterParams) {
        return buildQuery(filterParams).get(fetch: fetchAll)
    }

    List<TMovie> list(Map filterParams = [:], Map fetchParams = [:]) {
        if (!fetchParams.sort) {
            fetchParams.sort = [dateCreated: 'asc']
        }
        if (!fetchParams.fetch) {
            fetchParams.fetch = fetch
        }

        def query = buildQuery(filterParams)
        return query.list(fetchParams)
    }

    Number count(Map filterParams = [:]) {
        def query = buildQuery(filterParams)
        return query.count()
    }

    @Transactional
    TMovie create(Map args = [:]) {
        if (args.failOnError == null) {
            args.failOnError = false
        }

        TMovie obj = new TMovie(args)
        obj.save(flush: true, failOnError: args.failOnError)

        return obj
    }

    @Transactional
    @CompileDynamic
    @Requires({ args.id })
    TMovie update(Map args = [:]) {
        if (args.failOnError == null) {
            args.failOnError = false
        }

        TMovie obj = get(args.id)
        obj.properties = args
        obj.save(flush: true, failOnError: args.failOnError)

        return obj
    }

    @Transactional
    void delete(Serializable id) {
        TMovie obj = get(id)
        if (obj) {
            obj.delete(flush: true)
        }
    }
}
----

Run the application with `./gradlew bootRun`. You can then create, list, edit, and delete movies.
