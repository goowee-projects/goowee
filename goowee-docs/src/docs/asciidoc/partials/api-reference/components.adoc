[[components]]
== Components

=== Component (abstract)

Everything in Goowee is a `Component`. A component is a small web application with an HTML view, CSS styling, and JavaScript logic. It can also provide a supporting `Service` or `Controller`.

You do not need to know HTML, CSS, or JavaScript to develop a Goowee application unless you want to create a new component.

Each component extends the base class `Component`, so all components share the following properties and methods.

==== Properties
[cols="1,1,1,7a"]
|===
|Property|Type|Default|Description

|`id`
|`String`
|Required
|Id of the component instance. This is mandatory, it must be unique and provided in the constructor.
|`visible`
|`Boolean`
|`true`
|Shows or hides the component without changing the layout
|`display`
|`Boolean`
|`true`
|Displays or hides the component, adding or removing it from the layout
|`readonly`
|`Boolean`
|`false`
|Readonly controls are disabled
|`skipFocus`
|`Boolean`
|`false`
|The component won't participate in keyboard or mouse selection
|`sticky`
|`Boolean`
|`null`
|The component is sticky on top
|`containerSpecs`
|`Map`
|`[:]` (with `attributes: [:]`)
|Contains instructions for the container. The container component may or may not respect them, see the documentation for the specific container component.
|`textColor`
|`String`
|`null`
|The text color, CSS format
|`backgroundColor`
|`String`
|`null`
|Background color, CSS format
|`cssClass`
|`String`
|`''`
|Custom CSS class to apply. The CSS class must be a https://getbootstrap.com/[Bootstrap,window=_blank] CSS class or a custom one declared in the `grails-app/assets/stylesheets/goowee.css` file. See <<custom-css>>.
|===

==== Methods
[cols="2,8a"]
|===
|Method|Description

|`addComponent(Map)`
|Adds a component as children. See <<components>>.
|`addControl(Map)`
|Adds a control as children. See <<controls>>.
|`on(Map)`
|Configures an event. See <<events>>.
|===

[[grid]]
=== Grid
A `Grid` lays out components in responsive columns using the Bootstrap grid system. Add columns with `addColumn(Map)` and add components or controls to each returned `GridColumn`.

[source,groovy]
----
def grid = c.addComponent(
    class: Grid,
    id: 'summary',
)
grid.setBreakpoints(12, 6, 4, 4, 3, 2)

grid.addColumn().addComponent(
    class: Label,
    id: 'status',
    text: 'Ready',
)
----

==== Properties
[cols="1,1,1,7a"]
|===
|Property|Type|Default|Description

|`spacing`
|`Integer`
|`1`
|The gutter spacing between columns, corresponding to the Bootstrap `g-N` class.
|`tag`
|`Boolean`
|`false`
|Whether the grid renders as an HTML element instead of a CSS-only container.
|`xs`, `sm`, `md`, `lg`, `xl`, `xxl`
|`Integer`
|`null` (each breakpoint)
|The default column span at each Bootstrap breakpoint. An unset breakpoint inherits the applicable wider-breakpoint behavior.
|===

==== Methods
[cols="2,8a"]
|===
|Method|Description

|`addColumn(Map)`
|Adds a `GridColumn` and returns it. The map accepts component properties and breakpoint values.
|`setBreakpoints(Integer xs, Integer sm, Integer md, Integer lg, Integer xl, Integer xxl)`
|Sets all default column spans. With no arguments, the values are `12`, `6`, `4`, `4`, `3`, and `2` respectively.
|===

[[grid-column]]
=== GridColumn
A `GridColumn` is returned by `Grid.addColumn()` and holds the components arranged in that column. Its breakpoint values override the corresponding values set on the parent `Grid`; unset values inherit from the grid.

==== Properties
[cols="1,1,1,7a"]
|===
|Property|Type|Default|Description

|`xs`, `sm`, `md`, `lg`, `xl`, `xxl`
|`Integer`
|`null` (each breakpoint)
|Column span at the corresponding Bootstrap breakpoint. A value set on the column overrides the same breakpoint on its parent grid.
|`scrollable`
|`Boolean`
|`false`
|Whether the column content can scroll independently.
|===

[[header_]]
=== Header
A `Header` is a bar at the top of the `Content` area. It can stay fixed at the top or scroll with the content. Its main purpose is to hold navigation buttons.

A `Header` can have a `backButton` on the left, a `nextButton` on the right, and a `text` in the middle.

==== Properties
[cols="1,1,1,7a"]
|===
|Property|Type|Default|Description

|`sticky`
|`Boolean`
|`null`
|When set to `true` the header will stick on top. Adding a `backButton` or `nextButton` does not change this property. Set `sticky` explicitly to `true` to keep the header and its buttons visible while scrolling, or to `false` to make the header scroll with the content.
|`text`
|`String`
|Current `controller.action.id` message key
|The title text to display
|`textArgs`
|`List`
|`[]`
|Args to use when looking up an i18n message. For example, if `messages.properties` contains `book.index.header=Books for {0} {1}` and `textArgs = ['Mario', 'Rossi']`, the rendered text will be `Books for Mario Rossi`.
|`icon`
|`String`
|`null`
|An icon to be displayed before the title text. We can choose one from https://fontawesome.com/[Font Awesome,window=_blank]
|`hasBackButton`
|`Boolean`
|`false`
|`true` if a `backButton` has been added
|`hasNextButton`
|`Boolean`
|`false`
|`true` if a `nextButton` has been added
|`backButton`
|`Button`
|`null`
|The back button object. See <<button>>
|`nextButton`
|`Button`
|`null`
|The next button object. See <<button>>
|===

==== Methods
[cols="2,8a"]
|===
|Method|Description

|`addBackButton(Map)`
|Add the backButton. Accepts the arguments of <<button>>
|`removeBackButton()`
|Removes the backButton. Does nothing if no backButton has been added.
|`addNextButton(Map)`
|Add the nextButton. Accepts the arguments of <<button>>
|`removeNextButton()`
|Removes the nextButton. Does nothing if no nextButton has been added.
|===

[[table]]
=== Table
A `Table` is a convenient way to display a recordset.

Each table can have <<table-filters>>, and each row can have its own action buttons. The available actions can depend on the logged-in user and the record's status.

==== Properties
[cols="1,1,1,7a"]
|===
|Property|Type|Default|Description

|`columns`
|`List<String>`
|`[]`
|Names or dot-separated property paths of the columns to display. For map or object records, each name must resolve to a value; for list records, values are displayed in the specified column order.
[source,groovy]
----
    c.table.with {
        columns = [
            'title',
            'author',
        ]
    }
----
|`keys`
|`List<String>`
|`[]`
|Record property names used as row keys and submitted with row actions. If no keys are set, the table uses `id` when records have an `id` property; otherwise, it uses the first column. Key values are stored in hidden fields; developer display hints may add key columns to the table.
[source,groovy]
----
c.table.with {
    keys = [
        'publisher_id',
    ]
}
----
|`sortable`
|`Map<String, String>`
|`[:]`
|Maps sortable column names to their initial sort directions (`asc` or `desc`). Setting this property also initializes the table's sort order.
[source,groovy]
----
c.table.with {
    sortable = [
        title: 'asc',
    ]
}
----
|`sort`
|`Map<String, String>`
|`[:]`
|Default sort order for the records. The current sort state is maintained in this map and in `fetchParams`; use `sortable` to enable clickable sort headers.
[source,groovy]
----
c.table.with {
    sort = [
        title: 'asc',
    ]
}
----
|`submit`
|`List<String>`
|`[]`
|Column names whose values are included in the parameters submitted with each row action.
[source,groovy]
----
c.table.with {
    submit = [
        'author',
    ]
}
----
|`submitParams`
|`Map<String, Object>`
|`[:]`
|Additional parameters merged into row-action and filter-action requests.
|`labels`
|`Map<String, String>`
|`[:]`
|Overrides the displayed header label for the specified columns.
[source,groovy]
----
c.table.with {
    labels = [
        author: '-',
    ]
}
----
|`transformers`
|`Map<String, String>`
|`[:]`
|Maps column names to registered transformer names. Each row value in that column is processed by the specified transformer. See <<registerTransformer()>>.
[source,groovy]
----
c.table.with {
    transformers = [
        title: 'UPPERCASE_TITLE',
    ]
}
----
|`prettyPrinters`
|`Map<String, Object>`
|`[:]`
|Maps column names to registered pretty printer names or classes. See <<registerPrettyPrinter()>>.
[source,groovy]
----
c.table.with {
    prettyPrinters = [
        title: 'BOOK_TITLE',
    ]
}
----
|`prettyPrinterProperties`
|`Map<String, Map>`
|`[:]`
|Maps column names to pretty printer properties applied to the cell's values. See <<pretty-printer-properties>>.
[source,groovy]
----
c.table.with {
    prettyPrinterProperties = [
        salary: [
            highlightNegative: false,
            renderZero: '-',
        ],
        name: [
            renderTextPrefix: true,
        ],
    ]
}
----
|`title`
|`Separator`
|Hidden by default
|Optional separator above the table. Set `title.text` and `title.display = true` to show a title.
|`stickyHeader`
|`Boolean`
|`true`
|If `true` the table header will stick to top when scrolling. Not available in modals.
|`rowActions`
|`Boolean`
|`true`
|Whether to display row action buttons. They are hidden when the table is read-only.
|`hasHeader`
|`Boolean`
|`true`
|Whether to display the table header or not
|`hasFooter`
|`Boolean`
|`true`
|Whether to display the table footer or not
|`hasPagination`
|`Boolean`
|`false`
|Whether to display the table pagination or not
|`hasComponents`
|`Boolean`
|`false`
|Whether to render custom components in table cells. Enabling this feature slows down rendering.
|`widths`
|`Map<String, Integer>`
|`[:]`
|Sets the width, in pixels, of the specified columns.
|`includeValues`
|`List<String>`
|`[]`
|For GORM recordsets, adds the named properties to each row's values map, including properties not listed among the domain's persistent properties. This option does not affect map or list recordsets.
|`excludeValues`
|`List<String>`
|`[]`
|Omits the named properties from each row's values map for GORM and POJO recordsets. Map and list recordsets are not filtered.
|`stickyHeaderOffset`
|`Double`
|`null`
|Offset, in pixels, applied to the sticky table header. When unset or `0`, the page's sticky-box offset is used.
|`stickyHeaderZIndex`
|`Integer`
|`0`
|The CSS `z-index` applied to the sticky table header.
|`rowHighlight`
|`Boolean`
|`true`
|Whether to highlight the rows on mouse pointer hover
|`rowStriped`
|`Boolean`
|`false`
|Whether to apply alternating row stripes.
|`rowBorderless`
|`Boolean`
|`true`
|Whether to omit borders between table rows.
|`rowScrollToLastChanged`
|`Boolean`
|`false`
|Currently has no effect; the table rendering and client code do not use this property.
|`rowHighlightLastChanged`
|`Boolean`
|`false`
|Currently has no effect; the table rendering and client code do not use this property.
|`noResults`
|`Boolean`
|`true`
|Whether to display the no-results message when the table has no rows.
|`noResultsIcon`
|`String`
|`'fa-regular fa-folder-open mb-n2'`
|Icon classes for the no-results message. Choose an icon from https://fontawesome.com/[Font Awesome,window=_blank].
|`noResultsMessage`
|`String`
|`'component.table.no.results'`
|Message key for the text displayed when the table has no results.

==== Table child components
`Table` creates and manages the components used to render its rows and controls. Use the corresponding `Table` properties and methods to work with them:

[cols="1,1,6a"]
|===
|Component|Access|Role

|`TableRowset`
|`header`, `body`, `footer`
|Holds the table's column headings, data rows, or footer rows. Assign recordsets through these properties; use `body.eachRow` to configure individual rows.
|`TableRow`
|The `row` argument of `body.eachRow`
|Represents one row and exposes its cells and row actions.
|`TableCell`
|`row.cells[columnName]`
|Represents a cell. It can contain a label or, when `hasComponents` is enabled, a component.
|`TableFilters`
|`filters`
|Holds the table's filter fields and manages the filter search and reset actions. Define the fields through `filters`; their submitted values are available through `filterParams`. See <<table-filters>>.
[source,groovy]
----
c.table.with {
    filters.with {
        addField(
            class: TextField,
            id: 'title',
            cols: 6,
        )
        addField(
            class: TextField,
            id: 'author',
            cols: 6,
        )
    }
}

Map filters = c.table.filterParams // <1>
----
<1> The submitted values of the filter fields.
|`Button`
|`actions`
|Configures the actions shown on each row. Defaults to _Edit_ and _Delete_; added actions are copied to every row. See <<table-row-actions>>.
|`Button`
|`groupActions`
|Configures actions for selected rows. The button appears when one or more rows are selected. See <<table-group-actions>>.
|`TableActionbar`
|`actionbar`
|Hosts actions above the table, including filter actions.
|`TableDataset`
|`dataset`
|Carries data exchanged with the client when table results are fetched.
|`TablePagination`
|`pagination`
|Manages the table's page offset, page size, and total row count.
|===

==== Methods
[cols="2,8a"]
|===
|Method|Description

|`body`
|Assigns a recordset to the table body (See <<recordsets>>)
[source,groovy]
----

----
|`footer`
|Assigns a recordset to the table footer (See <<recordsets>>)
[source,groovy]
----
c.table.footer = bookService.listTotals()
----
|`paginate`
|If set the table will paginate the results. Must be set to the total count of the records to show.
[source,groovy]
----
c.table.paginate = bookService.count()
----
|`fetchParams`
|Contains the current sort and pagination values for fetching table records. You can add other fetch options here and pass the map to the service that loads the records.
[source,groovy]
----
Map fetchParams = c.table.fetchParams
----
|`filterParams`
|Returns the current filter values as a map keyed by filter field ID. Values are initialized from the request, action session, or defaults. Pass this map to the service that filters the records.
[source,groovy]

----
|`getFilter(String id)`
|Returns the current value of the named filter. The value is initialized from the request, action session, default value, or a filter reset when needed. Returns `null` if the filter id is unknown.
|`setFilter(String id, Object value)`
|Sets the named filter value and synchronizes it with the filter control, action session, and request parameters.
|`resetFilters()`
|Clears the saved filter values from the action session. It does not change the table's pagination.
|`resetPagination()`
|Resets the offset to `0` and the page size to `20`, retaining filter values. Explicit `_21TableOffset` or `_21TableMax` request parameters are preserved.

|This closure gets called for each row displayed by the table. Don't execute slow code here since it will slow down the whole table rendering.
[source,groovy]
----

    row.cells['title'] // <2>
    row.actions // <3>
}
----
<1> The record values
<2> See <<label>>
<3> See <<table-row-actions>>

[[recordsets]]
==== Recordsets
What data can you use to populate a table?

===== List of Lists
You can populate a table with a list of lists. The position of each value determines the column it appears in, so column names are not tied to specific values.

For this reason, we recommend using a <<list-of-maps>> instead.

[source,groovy]
----
c.table.columns = [
    'title',
    'author',
    'description',
]

c.table.body = [
    ['The Teachings of Don Juan', 'Carlos Castaneda', 'This is a nice fictional book'],
    ['The Antipodes of the Mind', 'Benny Shanon', 'This is a nice scientific book'],
]
----

[[list-of-maps]]
===== List of Maps
You can also populate a table with a recordset-style data structure such as a list of maps. Each column then displays the value associated with the matching key in each record (`Map`).

[source,groovy]
----
c.table.columns = [
    'title',
    'author',
    'id',
]

c.table.body = [
    [id: '1', title: 'The Teachings of Don Juan', author: 'Carlos Castaneda', description: 'This is a nice fictional book'],
    [id: '2', title: 'The Antipodes of the Mind', author: 'Benny Shanon', description: 'This is a nice scientific book'],
]
----

===== List of POGOs
You can also populate a table with a list of _Plain Old Groovy Objects_ (POGOs).

For example, given this POGO:
[source,groovy]
----
class Book {
    String id
    String title
    Strng author
    String description
}
----

Populate the table as follows:

[source,groovy]
----
c.table.columns = [
    'title',
    'author',
    'id',
]

c.table.body = [
    new Book(id: '1', title: 'The Teachings of Don Juan', author: 'Carlos Castaneda', description: 'This is a nice fictional book'),
    new Book(id: '2', title: 'The Antipodes of the Mind', author: 'Benny Shanon', description: 'This is a nice scientific book'),
]
----

===== GORM Recordsets
You can also populate a table from a https://gorm.grails.org/latest/hibernate/manual/[GORM recordset,window=_blank]. See how to build a xref:{quick-start-xref}[CRUD].

[source,groovy]
----
c.table.columns = [
    'title',
    'author',
]

c.table.body = TBook.list()
c.table.paginate = TBook.count()
----

[[table-row-actions]]
==== Row Actions
You can configure row actions for all rows at once or individually. To give every row the same actions, configure them in the table namespace:

[source,groovy]
----
c.table.with {
    columns = [
        'title',
        'author',
    ]
    actions.addAction(action: 'borrow') // <1>
    actions.addAction(action: 'return')
}
----
<1> See <<button>> for all the `Button` properties

To configure row actions based on record values or other conditions, use the `eachRow` closure.

[source,groovy]
----
c.table.with {
    columns = [
        'title',
        'author',
    ]

    body.eachRow {
        if (values.borrowed) {
            row.actions.addAction(action: 'return') // <1>
        } else {
            row.actions.addAction(action: 'borrow')
        }
    }
}
----
<1> See <<button>> for all the `Button` properties

[[table-group-actions]]
==== Group Actions
Configure the table to select multiple rows and apply the same action to all of them.

[source,groovy]
----
c.table.with {
    columns = [
        'title',
        'author',
    ]

    groupActions.addAction(action: 'return') // <1>
    groupActions.addAction(action: 'borrow')
}
----
<1> See <<button>> for all the `Button` properties

[[table-filters]]
=== TableFilters
Each table can have its own search `Form` to filter results. When the filters are submitted, the action that contains them is reloaded, and their values are available in the Grails `params` map.

Use the parent `Table`'s `getFilter(id)` and `setFilter(id, value)` methods to read or update one filter. Pass the `id` used with `addField()`; the `filters.` prefix is used for the localized label, not for the filter id. `getFilter()` resolves the current value from the request, action session, or default value. `setFilter()` updates the control and synchronizes the value with the action session and request parameters.

[source,groovy]
----
// Set a filter value programmatically
c.table.setFilter('status', 'PUBLISHED')

// Read the current value of that filter
def status = c.table.getFilter('status')
----

To clear the saved filter state or reset paging, call the parent `Table` methods. `resetFilters()` removes filter values from the action session without changing pagination. `resetPagination()` resets the offset and page size while retaining filters; explicit `_21TableOffset` and `_21TableMax` request parameters take precedence.

[source,groovy]
----
c.table.resetFilters()
c.table.resetPagination()
----

[source,groovy]
----
c.table.with {
    filters.with {
        addField(
            class: Select,
            optionsFromRecordset: bookService.list(),
            prettyPrinter: 'BOOK',
            id: 'book',
            cols: 4,
        )
        addField(
            class: TextField,
            id: 'search',
            cols: 8,
        )
    }

    Map filters = c.table.filterParams // <1>
}
----
<1> The submitted values of the filter fields.

==== Properties
[cols="1,1,1,7a"]
|===
|Property|Type|Default|Description

|`isFiltering`
|`Boolean`
|`false` (before filtering)
|`true` if the filters form has values in its fields
|`fold`
|`Boolean`
|`true` on mobile; otherwise `false`
|Whether the filters form is displayed as folded or not at its first appearance. After that its folded state will be stored in the session.
|`autoFold`
|`Boolean`
|`true` on mobile; otherwise `false`
|If set to `true` the filters form will be folded each time a search is submitted
|===

==== Methods
[cols="2,8a"]
|===
|Method|Description

|`addField()`
|Adds a form field. See <<form-field>> and <<controls>>
|`getValue(String id)`
|Returns the current value of the named filter after applying its initialization rules. Returns `null` if the filter id is unknown.
|`setValue(String id, Object value)`
|Sets the filter control's value and synchronizes it with the action session and request parameters. The parent `Table` exposes these operations as `getFilter()` and `setFilter()`.
|===

[[form]]
=== Form
A `Form` lays out <<components>> and <<controls>> in a 12-column grid for arranging form fields horizontally.

On mobile devices, all fields are displayed in a single column, making them easier to use when horizontal space is limited.

[source,groovy]
----
c.form.with {
    addField(
        class: TextField,
        id: 'title',
        cols: 6,
    )
    addField(
        class: TextField,
        id: 'author',
        cols: 6,
    )
}
----

As an alternative to map-based configuration, pass the component class and id as
declared arguments and configure the created component and `FormField` through typed
closure parameters. Declaring both parameter types enables IDE completion for their
properties and methods:

[source,groovy]
----
c.form.addField(TextField, 'title') { TextField control, FormField field ->
    control.placeholder = 'Book title'
    control.autocomplete = true

    field.label = 'Title'
    field.help = 'Enter the complete title'
    field.cols = 6
}
----

The closure runs after Goowee has created both objects and applied the usual defaults
and validation constraints. Use the first parameter for the control or component and
the second for layout and field metadata. Goowee applies a control's `defaultValue`
after the closure has run.

Properties with derived state can also be configured this way. For example, setting
`decimals` updates a number field's input mode, date boundaries accept `LocalDate`,
`LocalTime`, or `LocalDateTime`, and option-based controls expose typed option-source
setters:

[source,groovy]
----
c.form.addField(Select, 'status') { Select control, FormField field ->
    control.exclude = [Status.ARCHIVED]
    control.optionsFromEnum = Status
    control.multiple = true

    field.cols = 6
}
----

Configure `keys`, `keysSeparator`, `exclude`, `forEachOption`, and pretty-printing
properties before assigning `optionsFromRecordset`, `optionsFromList`, or
`optionsFromEnum`, because assigning the option source builds the resolved options.

==== Properties
[cols="1,1,1,7a"]
|===
|Property|Type|Default|Description

|`validate`
|`Class`
|`null`
|A `grails.validation.Validateable` class or a GORM domain class used to automatically render the field as required. A red `*` will be displayed next to the field label if appropriate.
|`readonly`
|`Boolean`
|`false`
|Sets all the form fields readonly
|`autocomplete`
|`Boolean`
|`false`
|Whether the browser can autocomplete fields in the form.
|`autofocus`
|`Boolean`
|`true`
|Whether the form should focus the first available field.
|===

==== Methods
[cols="2,8a"]
|===
|Method|Description

|`addField()`
|Adds a form field. Use `addField(Map)` for map-based construction, or
`addField(Class, String, Closure)` for typed component and field configuration.
See <<form-field>> and <<controls>>.
|===

[[form-field]]
=== FormField
A form field wraps a `Control` with a label and places it in the grid. A `FormField` is created automatically whenever you add a field to a `Form` using its `addField()` method.

==== Properties
[cols="1,1,1,7a"]
|===
|Name|Type|Default|Description

|`component`
|`Component`
|Required
|The contained component
|`label`
|`String`
|Current `controller.id` message key when created by `Form.addField()`
|The field label
|`labelArgs`
|`List`
|`[]`
|A list of objects to pass to the localized message (Eg. when using `{0}` in `message.properties`)
|`help`
|`String`
|`''` when created by `Form.addField()`
|A help message
|`helpArgs`

[[button]]
=== Button
Buttons let users trigger actions in the GUI. A `Button` can expose multiple actions.

A single button can display two directly accessible actions, `defaultAction` and `tailAction`, plus a menu of links called `actionMenu`.

[%autowidth]
[cols="2,2,2"]

A simple button will have just the `defaultAction`.

[source,groovy]

c.form.with {
    def addBookField = addField( // <1>

[[image]]
=== Image
An `Image` displays an image from a browser-readable URL or path. Inside a form, `rows` sets the field height unless both `keepAspectRatio` and `fitWidth` are `true`. In that case, the image fills the available width, keeps its aspect ratio, and determines its own height. Set `keepAspectRatio` to `false` to stretch the image to fill the field. When preserving the aspect ratio and `fitWidth` is `false`, unused space is transparent by default; set the inherited `backgroundColor` property to fill it with a color.

[source,groovy]
----
c.form.with {
    addField(
        class: Image,
        id: 'loginBackground',
        image: linkPublicResource('brand/login-background.jpg', false),
        keepAspectRatio: true,
        fitWidth: false,
        padding: 1,
        cols: 12,
        rows: 3,
    )
}
----

==== Properties
[cols="1,1,1,7a"]
|===
|Name|Type|Default|Description

|`image`
|`String`
|`null`
|The browser-readable URL or path of the image to display. For a tenant public resource, use `linkPublicResource(...)`.
|`keepAspectRatio`
|`Boolean`
|`true`
|When `true`, preserves the image's aspect ratio within the form field. When `false`, stretches the image to fill the field's width and height, including the height set by `rows`.
|`fitWidth`
|`Boolean`
|`false`
|When `keepAspectRatio` is `true` and `fitWidth` is `true`, sizes the image to the full field width and keeps its natural aspect ratio; the field height follows the image and ignores `rows`. When `keepAspectRatio` is `true` and `fitWidth` is `false`, the image fits within the field height and any unused space is transparent by default. This property has no effect when `keepAspectRatio` is `false`.
|`padding`
|`Double`
|`0`
|Inner spacing between the image and its edge, in `rem`. For example, `padding: 1` adds `1rem` on each side. Negative values are treated as `0`.
|===

[[key-press]]
=== PageKeyPress
`PageKeyPress` is a standard component created automatically for every `Page`. It provides page-wide keyboard hotkeys and detects fast input from barcode and RFID readers. With a trigger key configured, the client buffers characters and uses their timing to distinguish scanner input from ordinary typing. When it detects scanner-speed input followed by the trigger key, it sends the value with the configured event. The server receives it as `_21KeyPressed`; controller actions can read it through `keyPressed`.

Configure the page's existing component through the nested `keyPress` map when creating the page. Do not create a separate `PageKeyPress` with `addComponent` or `createComponent`.

[source,groovy]
----
def page = createPage(PageBlank, [
    keyPress: [
        enabled: true,
        triggerKey: 'Enter',
        hideInput: true,
    ],
])
----
The nested map accepts the component properties and the event options `controller`, `action`, `namespace`, `params`, and `submit`. By default the event invokes `keyPress/onKeyPress`.

When `hideInput` is enabled, scanner-speed characters are removed from a focused input while ordinary typing remains in the field. The `PageKeyPress` component also handles hotkeys configured on `Link` components.

==== Properties
[cols="1,1,1,7a"]
|===
|Name|Type|Default|Description

|`triggerKey`
|`String`
|`'Enter'`
|Characters are buffered until the trigger key is pressed. The event is dispatched when the buffered sequence is recognized as scanner-speed input. The trigger key can be any character or `Enter`. If blank (`''`), each key meets the trigger condition.
|`enabled`
|`Boolean`
|`true`
|Whether scanner input detection is enabled.
|`hideInput`
|`Boolean`
|`true`
|When `true`, scanner-speed input is removed from the focused input field. When `false`, the field is left unchanged by PageKeyPress.
|===

==== Events
[cols="2,8a"]
|===
|Event|Description

|`keypress`
|Triggered when scanner-speed input ends with the configured `triggerKey`. The collected value is sent as `_21KeyPressed`. When `triggerKey` is blank, each key meets the trigger condition.
|===
