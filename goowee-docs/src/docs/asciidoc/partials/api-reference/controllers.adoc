[[controllers]]
== Controllers & Actions

=== Controllers
A controller contains a set of actions. When a user interacts with the GUI, an action can run application logic. Group actions into controllers to organize the application around its business domain.

A controller is a Groovy class, and each method is an action. The following example shows a Goowee controller for CRUD operations.

.grails-app/controllers/BookController.groovy
[source,groovy]
----
@Secured(['ROLE_CAN_EDIT_BOOKS']) // <1>
class BookController implements ElementsController { // <2>

    def index() {
        // will display a list of books
    }

    def create() { //<3>
        // will display a form with book title and author
    }

    def onCreate() { // <3>
        // will create the book record on the database
    }

    def edit() {
        // will display the details of a book
    }

    def onEdit() {
        // will update the book record on the database
    }

    def onDelete() {
        // will delete a book from the database
    }
}
----
<1> The `@Secured` annotation restricts access to this controller's actions to users with the `ROLE_CAN_EDIT_BOOKS` authority.
<2> Implementing `ElementsController` makes the Goowee API available.
<3> By convention, actions that build and display a GUI are named after a verb or a noun, while actions that execute business logic start with `on`.

=== Actions
An action can build an interactive graphical user interface (GUI), or serve as an entry point for business logic that can update the user interface if needed.

Keep business logic in https://docs.grails.org/latest/guide/services.html[Grails services,window=_blank] rather than controller actions, following Grails conventions and best practices.

To display a GUI, build it using <<contents>> and <<components>>. The following example creates a GUI to list, create, and edit books:

.grails-app/controllers/BookController.groovy
[source,groovy]
----
@Secured(['ROLE_CAN_EDIT_BOOKS'])
class BookController implements ElementsController {

    BookService bookService // <1>

    def index() {
        def c = createContent(ContentTable) // <2>

        c.table.with {
            columns = [
                'title',
                'author',
            ]
            body = bookService.list()
        }

        display content: c
    }

    private buildForm(Map obj = null) {
        def c = obj // <3>
                ? createContent(ContentEdit)
                : createContent(ContentCreate)

        c.form.with {
            addField(
                class: TextField,
                id: 'title',
            )
            addField(
                class: TextField,
                id: 'author',
            )
        }

        if (obj) {
            c.form.values = obj
        }

        return c
    }

    def create() {
        def c = buildForm()
        display content: c, modal: true
    }

    def edit() {
        def book = bookService.get(params.id)
        def c = buildForm(book)
        display content: c, modal: true
    }
}
----
<1> The `BookService` service implements the business logic
<2> `createContent()` instantiates one of the available <<contents>> to display a list of records
<3> The GUI we build for the `create` and `edit` actions is the same. We make sure to use the appropriate content for creating and editing (See <<contents>>)

Each action ends with a `display` statement that renders the composed GUI in the browser.

The `BookService` implements CRUD operations for a simple in-memory database.

.grails-app/services/BookService.groovy
[source,groovy]
----
import groovy.contracts.Requires

@CompileStatic
class BookService {

    private static final data = [
        [id: 1, title: 'The Teachings of Don Juan', author: 'Carlos Castaneda', description: 'This is a nice fictional book'],
        [id: 2, title: 'The Antipodes of the Mind', author: 'Benny Shanon', description: 'This is a nice scientific book'],
    ]

    List<Map> list() {
        return data
    }

    Map get(Serializable id) {
        return data.find { it.id == id }
    }

    void create(Map record) {
        record.id = data.size() + 1
        data.add(record)
    }

    @Requires({ record.id })
    void update(Map record) {
        Map item = data.find { it.id == record.id }
        if (item) {
            item.title == record.title
            item.author = record.author
        }
    }

    void delete(Serializable id) {
        data.removeAll { it.id == id }
    }
}
----

[[validation]]
=== Validation
Validate user input before saving it. You can use the standard https://docs.grails.org/latest/guide/validation.html[Grails validation,window=_blank] for this.

This example uses the https://docs.grails.org/latest/guide/validation.html#:~:text=11.6%20Applying%20Validation%20to%20Other%20Classes[Validateable trait,window=_blank] to check that fields are not null and that the title is unique. See the https://docs.grails.org/latest/guide/validation.html[Grails validation,window=_blank] documentation for all available options.

.grails-app/controllers/BookValidator.groovy
[source,groovy]
----
class BookValidator implements Validateable {

    String title
    String author

    BookService bookService

    static constraints = {
        title validator: { Object val, BookValidator obj, Errors errors ->
            if (obj.bookService.getByTitle(val)) {
                errors.rejectValue('title', ValidationError.IS_NOT_UNIQUE)
            }
        }
    }
}
----

Now implement the complete CRUD interface:

.grails-app/controllers/BookController.groovy
[source,groovy]
----
class BookController implements ElementsController {

    BookService bookService

    def index() {
        def c = createContent(ContentTable)

        c.table.with {
            columns = [
                'title',
                'author',
            ]
            body = bookService.list()
        }

        display content: c
    }

    private buildForm(Map obj = null) {
        def c = obj
                ? createContent(ContentEdit)
                : createContent(ContentCreate)

        c.form.with {
            addField(
                class: TextField,
                id: 'title',
            )
            addField(
                class: TextField,
                id: 'author',
            )
        }

        if (obj) {
            c.form.values = obj
        }

        return c
    }

    def create() {
        def c = buildForm()
        display content: c, modal: true
    }

    def onCreate(BookValidator obj) { // <2>
        if (obj.hasErrors()) {
            display errors: obj // <1>
            return
        }

        bookService.create(params)
        display action: 'index'
    }

    def edit() {
        def book = bookService.get(params.id)
        def c = buildForm(book)
        display content: c, modal: true
    }

    def onEdit(BookValidator obj) { // <2>
        if (obj.hasErrors()) {
            display errors: obj // <1>
            return
        }

        bookService.update(params)
        display action: 'index'
    }

    def onDelete() { // <2>
        try {
            bookService.delete(params.id)
            display action: 'index'

        } catch (Exception e) {
            display exception: e
        }
    }
}
----
<1> The `BookValidator` class checks that fields are not `null` and that the title is unique, and highlights invalid fields.
<2> The `ContentTable`, `ContentCreate`, and `ContentEdit` contents define these method names.

=== Internationalization (i18n)
When building the GUI, Goowee automatically suggests labels for components that need text. To translate a label, add its key and translation to the appropriate `grails-app/i18n/messages_*.properties` file.

For example, to enable English and Italian, add the following entries.

English:

.grails-app/i18n/messages.properties.groovy
[source]
----
feature.book.index=Books
book.index.header=Books
book.create.header=New Book
book.edit.header=Book
book.title=Title
book.author=Author
----

=== display()
The `display` method is a key Goowee feature. It renders the GUI on the server and sends it to the browser.

`display()` accepts a map of arguments. Some options apply to page or content rendering, while invocation options apply to redirects and message actions.

[cols="1,1,1,7a"]
|===
|Name|Type|Default|Description

|`page`
|`Page`
|
|Page to render. If omitted, the current session's main page is used. Specifying a page forces a full-page response.

|`content`
|`PageContent`
|
|Content to render in the page or transition. Render options can be passed as additional arguments. See <<contents>>.

|`transition`
|`Transition`
|
|Explicit transition to render in response to an AJAX request. If omitted, a transition is created automatically.

|`focus`
|`String`
|
|ID of the component to focus after rendering the transition.

|`loading`
|`Boolean`
|
|Whether to show the loading indicator while the transition is processed.

|`message`
|`String`
|
|Informational message to display in a message box.

|`messageArgs`
|`List`
|`[]`
|Arguments used to interpolate `message`, `confirmMessage`, or `errorMessage`.

|`confirmMessage`
|`String`
|
|Confirmation message to display in a dialog.

|`errorMessage`
|`String`
|
|Error message to display in a message box.

|`exception`
|`Exception`
|
|Exception whose message is displayed in a message box and whose details are logged.

|`errors`
|`Object`
|
|Validation errors to display on a submitted component. Accepts a field-to-message map or an object with an `errors` property, such as a `Validateable` or GORM domain instance.

|`controller`
|`String`
|
|Controller to redirect to. If omitted, the current controller is used.

|`action`
|`String`
|`index`
|Action to redirect to.

|`namespace`
|`String`
|
|Controller namespace for the redirect.

|`params`
|`Map<String, Object>`
|
|Request parameters to pass with the redirect.

|`url`
|`String`
|
|Explicit URL for the redirect. It takes precedence over `controller` and `action`; `direct` defaults to `true` when `url` is set.

|`path`
|`String`
|
|Absolute or relative path to use as the redirect target.

|`fragment`
|`String`
|
|URL fragment to append to the redirect target.

|`call`
|`String`
|
|Client-side JavaScript function to call instead of navigating.

|`direct`
|`Boolean`
|
|Whether to return a full HTML page or raw HTTP body instead of a `Transition`.

|`submit`
|`String` or `List<String>`
|
|Component names whose values should be submitted with the invocation.

|`target`
|`String`
|
|Browser context in which to open the redirect, such as `_self` or `_blank`.

|`targetNew`
|`Boolean`
|
|When `true`, opens the redirect in a new browser tab.

|`renderProperties`
|`PageRenderProperties`
|
|Rendering options to apply to the redirect destination. For `content`, pass the individual rendering options listed below.

|`infoMessage`
|`String`
|
|Informational message to display instead of running the click invocation associated with a message. This option applies when `message`, `confirmMessage`, or `errorMessage` is also specified.

|`modal`
|`Boolean`
|
|Whether to display the destination content in a modal dialog.

|`small`
|`Boolean`
|
|When displaying content in a modal, use a narrower layout.

|`large`
|`Boolean`
|
|When displaying content in a modal, use a wider layout.

|`fullscreen`
|`Boolean`
|
|When displaying content in a modal, use the full browser window.

|`closeButton`
|`Boolean`
|`true`
|Whether to show a close button on the modal dialog.

|`updateUrl`
|`Boolean`
|
|Whether to update the browser address bar with the destination URL.

|`animate`
|`String`
|
|CSS animation to apply when the destination content is displayed.

|`scroll`
|`String`
|
|Scroll behavior to apply after rendering the destination content.
|===
