[[custom-components]]
== Custom Components

A Goowee component joins a server-side model to a GSP template and a browser-side JavaScript class. CSS supplies its presentation. `goowee-core` includes `PieChart` and `BarChart`, both backed by a shared `Chart` model. This chapter uses `PieChart` to show how the parts fit together; Chart.js is optional for custom components that do not need charts.

The four parts have distinct responsibilities:

* The Groovy class receives the component configuration and selects the GSP template.
* The GSP renders HTML and exposes the component name, properties, and events through `data-21-*` attributes.
* The JavaScript class reads those attributes and initializes browser behaviour.
* The CSS file styles the component, while asset manifests load the CSS, JavaScript, and any third-party library in the correct order.

=== Structure

Keep the files under matching package and asset paths. The built-in chart components in `goowee-core` use this layout:

[source,text]
----
goowee-core/src/main/groovy/goowee/elements/components/
    Chart.groovy
    PieChart.groovy
    BarChart.groovy
goowee-core/grails-app/views/goowee/elements/components/
    _PieChart.gsp
    _BarChart.gsp
goowee-core/grails-app/assets/goowee/elements/components/
    PieChart.js
    PieChart.css
    BarChart.js
    BarChart.css
goowee-core/grails-app/assets/goowee/
    libs.min.js
    libs.min.css
    libs/
        chart-4.6.1.min.js
        chart-LICENSE.md
----

Core loads component JavaScript and CSS from its `elements/components` asset tree and loads Chart.js from `libs.min.js`. Application code can use `BarChart` and `PieChart` directly after depending on `goowee-core`.

The component does not have to use the `goowee.elements.components` package. If it uses a different GSP directory, set `viewPath` accordingly in the Groovy class. The GSP partial name must match `viewTemplate`, which defaults to the Groovy class's simple name.

For a component local to an application, the same pieces can live in that application's source, views, and asset directories. It needs an asset bundle registered as shown below.

The source excerpts below omit the license comment for readability. Every new source file committed to Goowee must include the canonical ASF license header used by the surrounding files.

=== Groovy Model

Every component extends `goowee.elements.core.Component` and accepts a `Map` constructor argument. The base constructor requires a unique `id`, registers any event arguments, and initializes common properties such as `visible`, `display`, `readonly`, `cssClass`, and `containerSpecs`.

The example extracts shared chart data into an abstract class:

.Core chart model: `goowee-core/src/main/groovy/goowee/elements/components/Chart.groovy`
[source,groovy]
----
package goowee.elements.components

import goowee.elements.core.Component
import groovy.transform.CompileStatic

@CompileStatic
abstract class Chart extends Component {

    List values
    List labels
    List colors

    Chart(Map args) {
        super(args)

        viewPath = '/goowee/elements/components/'

        values = args.values as List ?: []
        labels = args.labels as List ?: []
        colors = args.colors as List ?: []

        containerSpecs.multiline = true
    }

    @Override
    String getPropertiesAsJSON(Map properties = [:]) {
        Map thisProperties = [
            values: values,
            labels: labels,
            colors: colors,
        ]

        return super.getPropertiesAsJSON(thisProperties + properties)
    }
}
----

`getPropertiesAsJSON()` is the contract between Groovy and JavaScript. Always delegate to `super`: the base implementation adds standard component properties, removes empty values, and safely encodes the result as JSON. Do not build JSON or HTML attributes by string concatenation.

The concrete component supplies layout defaults:

.Core pie chart class: `goowee-core/src/main/groovy/goowee/elements/components/PieChart.groovy`
[source,groovy]
----
package goowee.elements.components

import groovy.transform.CompileStatic

@CompileStatic
class PieChart extends Chart {

    PieChart(Map args) {
        super(args)

        containerSpecs.rows = 8
    }
}
----

`containerSpecs` contains hints for a parent container. Here the chart requests eight rows. A parent that does not use these hints may ignore them.

=== GSP Template

Goowee renders a component using its `view` and passes the component itself to the template as `c`. Because `PieChart` keeps the default `viewTemplate`, its view is `/goowee/elements/components/PieChart`, resolved to the `_PieChart.gsp` partial.

.Core pie chart template: `goowee-core/grails-app/views/goowee/elements/components/_PieChart.gsp`
[source,gsp]
----
<div class="component-chart-pie ${c.cssClass}"
    data-21-component="${c.className}"
    data-21-id="${c.id}"
    data-21-properties="${c.propertiesAsJSON}"
    data-21-events="${c.eventsAsJSON}"
><canvas id="${c.id}"></canvas></div>
----

The root element is the component boundary. Preserve these attributes:

* `data-21-component` identifies the registered JavaScript class. The value is case-sensitive.
* `data-21-id` identifies this instance and must be unique on the page.
* `data-21-properties` carries the JSON produced by the Groovy class.
* `data-21-events` carries events registered by the base `Component` class.

Use `${c.cssClass}` so callers can add application-specific styling. When a component contains child Goowee components, render them with `<render:component>` or `<render:componentList>` instead of duplicating their markup.

=== JavaScript

The JavaScript class name must match the value of `c.className`. Extend the Goowee `Component` class, implement the lifecycle methods the component needs, and register the class after its declaration.

.Core pie chart script: `goowee-core/grails-app/assets/goowee/elements/components/PieChart.js`
[source,javascript]
----
class PieChart extends Component {
    static finalize($element, $root) {
        let properties = Component.getProperties($element);
        let canvas = $element.find('canvas')[0];

        new Chart(canvas, {
            type: 'pie',
            options: {
                maintainAspectRatio: false,
                events: ['mousemove', 'touchstart'],
            },
            data: {
                labels: properties.labels,
                datasets: [{
                    label: '',
                    data: properties.values,
                    backgroundColor: properties.colors,
                }],
            }
        });
    }
}

Component.register(PieChart);
----

Goowee calls `finalize($element, $root)` after the HTML has been inserted into the page. `$element` is the component's jQuery element and `$root` is the area being initialized. `Component.getProperties($element)` reads the server-side JSON contract. Scoping selectors to `$element` prevents one instance from changing another.

The base JavaScript class also provides helpers such as `Component.getId()`, `getProperty()`, `getEvent()`, and `getValues()`. Components that expose mutable standard properties can implement static setters following existing components, for example `static setText($element, value)`.

Finally, add the component styling:

.Core pie chart styles: `goowee-core/grails-app/assets/goowee/elements/components/PieChart.css`
[source,css]
----
.component-chart-pie {
    width: 100%;
    padding: 0.75rem;
}
----

Prefix selectors with a component-specific class so styles do not leak into the rest of the application.

=== Assets

For a custom component library, create JavaScript and CSS manifests. Dependencies must appear before the components that use them. The core chart components use `libs.min.js` for Chart.js and are loaded automatically from the core asset tree.

.Chart.js entry in the core library manifest: `goowee-core/grails-app/assets/goowee/libs.min.js`
[source,javascript]
----
//= require libs/chart-4.6.1.min
----

.Create `grails-app/assets/goowee/elements/elements-custom.js`
[source,javascript]
----
//= require ../libs.min

//= require components/MyComponent
----

.Create `grails-app/assets/goowee/elements/elements-custom.css`
[source,css]
----
/*
 *= require ../libs.min

 *= require components/MyComponent
 */
----

If you add more components, include their assets in these manifests. Keep third-party licenses with the assets and review their terms before distributing them.

Register the bundle during application or plugin startup:

.Edit `grails-app/init/com/example/BootStrap.groovy`
[source,groovy]
----
package com.example

import goowee.application.GooweeApplication
import groovy.transform.CompileStatic

@CompileStatic
class BootStrap {

    GooweeApplication gooweeApplication

    def init = {
        gooweeApplication.registerComponents('elements/elements-custom')
    }

    def destroy = {
    }
}
----

Pass the common asset path without the `.js` or `.css` extension. Goowee adds both compiled assets to every page. Registration is idempotent, but should normally happen only once for each custom bundle. Built-in core components need no additional registration.

=== Usage

Once the plugin and its assets are available, add the component like any other Goowee component. This example places it in a form so the container can apply its column and row specifications:

[source,groovy]
----
package com.example

import goowee.elements.ElementsController
import goowee.elements.components.PieChart
import goowee.elements.contents.ContentForm

class ChartsController implements ElementsController {

    def index() {
        def c = createContent(ContentForm)
        c.header.removeNextButton()

        c.form.addField(
            class: PieChart,
            id: 'salesByBrand',
            labels: ['FIAT', 'BMW', 'AUDI'],
            values: [100, 133, 167],
            colors: [
                'rgba(200, 0, 0, 0.6)',
                'rgba(0, 200, 0, 0.6)',
                'rgba(0, 0, 200, 0.6)',
            ],
            cols: 6,
        )

        display content: c
    }
}
----

The `id` must be unique within the page. Constructor arguments become Groovy properties, `getPropertiesAsJSON()` transfers the selected values, the GSP renders the component boundary, and `PieChart.finalize()` creates the Chart.js instance.

=== Checklist

Before considering a new component complete, verify that:

* the Groovy class calls `super(args)` and has a unique `id` when instantiated;
* `viewPath` and `viewTemplate` resolve to the intended GSP partial;
* the GSP root contains the four `data-21-*` attributes and includes `c.cssClass`;
* the Groovy and JavaScript class names match exactly;
* the JavaScript class calls `Component.register(...)`;
* the manifests load third-party libraries before dependent code and include the CSS file;
* the asset bundle is registered with `gooweeApplication.registerComponents(...)`;
* two instances can appear on the same page without sharing DOM state;
* empty, missing, and representative property values are handled; and
* server-side tests cover property/default behaviour, while a browser or integration test covers JavaScript initialization and interaction where practical.
