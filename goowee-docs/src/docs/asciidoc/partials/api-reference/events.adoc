[[events]]
== Events
Each `Component` can trigger one or more events. See <<components>> and <<controls>> for the events supported by each component.

Each event has a lowercase name. Configure an event directly when creating a component as follows.

[source,groovy]
----
c.form.with {
    addField(
        class: Select,
        id: 'book',
        onChange: 'books.onChangeBook', // <1>
        submit: ['form'],
    )
}
----
<1> The parameter name is `on` followed by the event name with its first letter capitalized. The value is an action name or a `controller.action` pair. If `submit` is omitted, this shorthand submits the component on which the event is registered.

When only the action is specified, the current controller is used. Use the dot
notation when the action belongs to another controller:

[source,groovy]
----
c.form.addField(
    class: Select,
    id: 'book',
    onChange: 'books.onChangeBook',
)
----

This invokes the `onChangeBook` action of the `books` controller. The same
target can be configured with the explicit `on()` method by specifying
`controller` and `action` separately. In `on(Map)`, both `event` and `action`
are required; `event` can be a string or a list of event names. If `controller`
is omitted, the current controller is used when one is available in the web
request; otherwise, specify it explicitly. Unlike the shorthand, `on(Map)` does
not submit component values unless `submit` is specified.

Multiple events can be configured as follows.

[source,groovy]
----
c.form.with {
    def book = addField(
        class: Select,
        id: 'book',
    ).component // <1>

    book.with {
        on( // <2>
            event: 'load',
            action: 'onLoadBooks',
        )
        on( // <3>
            event: 'change',
            controller: 'books',
            action: 'onChangeBook',
            submit: ['form'],
        )
    }
}
----
<1> References the component held by the `FormField`, not the form field itself.
<2> Configures the `load` event.
<3> Configures the `change` event for the `books` controller.

The following properties can be specified when configuring an event. Some options,
such as `target` and message dialogs, apply to `Link` events.

=== Properties
[cols="1,1,1,7a"]
|===
|Name|Type|Default|Description

|`event`
|`String` or `List<String>`
|Required by `on(Map)`
|The lowercase event name or names that trigger the action. The `onEvent` shorthand derives this from the parameter name (for example, `onChange` registers `change`).
|`namespace`
|`String`
|
|The namespace of the controller that handles the event.
|`controller`
|`String`
|Current controller, if available
|The controller that handles the event. When using the `onEvent` shorthand (for example, `onChange`), specify another controller in the action string as `controller.action`.
|`action`
|`String`
|Required by `on(Map)`; `index` for a `Link` when omitted
|The action to invoke. The `onEvent` shorthand takes an action name, optionally prefixed with a controller name.
|`call`
|`String`
|
|For a `Link`, calls a client-side JavaScript function instead of navigating. A dotted name can refer to a function on a global object, for example `myApp.refresh`.
|`params`
|`Map<String, Object>`
|
|Request parameters to pass to the event action.
|`url`
|`String`
|
|Explicit destination URL. If specified, it takes precedence over the `controller` and `action`. It makes `direct` default to `true` unless `direct` is explicitly set.
|`direct`
|`Boolean`
|`false`; `true` when `url` is supplied
|When `true`, navigates to the destination with a full browser page load instead of requesting and applying a `Transition`.
|`submit`
|`String` or `List<String>`
|
|IDs of the components or controls whose values are submitted with the event. The `onEvent` shorthand defaults this to the component on which the event is registered; `on(Map)` does not submit values by default.
|`target`
|`String`
|
|For a `Link`, the browser browsing context in which to open the destination (for example, `_blank` or `_self`). A target other than `_self` opens the destination in that context.
|`targetNew`
|`Boolean`
|`false`
|For a `Link`, setting this to `true` opens the destination in a new browser tab. It is a convenience property for `target: '_blank'` and `direct: true`.
|`loading`
|`Boolean`
|
|Whether to display a loading indicator while the event request is in progress. A `Link` displays one by default; `load` events default to no indicator.
|`infoMessage`
|`String`
|
|For a `Link`, displays an informational message instead of executing the link.
|`infoMessageArgs`
|`List`
|
|For a `Link`, arguments used to interpolate `infoMessage` through message lookup.
|`confirmMessage`
|`String`
|
|For a `Link`, asks the user to confirm before executing the link. If the user cancels, the link is not executed.
|`confirmMessageArgs`
|`List`
|
|For a `Link`, arguments used to interpolate `confirmMessage` through message lookup.
|`renderProperties`
|`PageRenderProperties` or `Map`
|
|Options for rendering the destination page content. The same options can be set directly on the event.
|`modal`
|`Boolean`
|
|Whether to display the destination content in a modal dialog.
|`small`
|`Boolean`
|
|When displaying content in a modal, use a narrower layout.
|`large`
|`Boolean`
|
|When displaying content in a modal, use a wider layout.
|`fullscreen`
|`Boolean`
|
|When displaying content in a modal, use the full browser window.
|`closeButton`
|`Boolean`
|
|Whether to show a close button on the modal dialog.
|`updateUrl`
|`Boolean`
|
|Whether to update the browser address bar with the destination URL. For event transitions, the client currently sets this automatically to `true` on desktop and `false` on mobile, overriding the configured value.
|`animate`
|`String`
|
|CSS animation to apply when the destination content is displayed.
|`scroll`
|`String`
|
|Scroll behavior to apply after rendering the destination content.
|===
